Title: Postgres schema + stored procedures for versioned workflow with Signwell approvals
Scope
Implement Postgres 14 schema contract for ops-first deal capture, immutable core.deal_version snapshots, deterministic approval requirements, and Signwell integration scaffolding. Postgres is the system of record. n8n is glue. Retool is the UI, Signwell is the external approval tool. Xero for financial drafts, posting and ingestion.

2) Stored procedures/functions (contract boundary)
1. ops.promote_draft_to_core(draft_id, submitted_by_identity_id) returns deal_version_id
2. core.is_send_eligible(deal_version_id, gate) returns boolean + reason
(or core.assert_send_eligible(...) raising exception)
• Checks:
o deal_version exists, current, correct gate
o required docs confirmed
o approval requirements resolved
o no active open envelope for that deal_version+gate
o deal_version not rejected/superseded
3. core.get_signwell_payload(deal_version_id, gate) returns jsonb
• Returns exact JSON payload required by n8n → Signwell API, built from:
o config.signwell_template
o config.signwell_field_dictionary
o core snapshot tables
4. core.ingest_signwell_webhook(payload jsonb) returns void
• Writes:
o audit.webhook_event (raw + dedupe)
o updates core.signwell_envelope*
o inserts audit.event_log
o inserts/updates core.approval_response equivalents
o advances/rejects gate per rules:
 G1/G3: any FIN_APPROVER signature completes (if using Signwell there)
 G2: all recipients must sign; any decline rejects
Acceptance tests
Goal: prove ops-first promotion works and enforces invariants.
Setup
• Insert minimal config: gate catalogue, doc checklist templates, approval rules, role catalogue
• Insert identities for ops + finance approver
• Create a valid ops draft with:
o deal subtype
o parties + JSE flag
o brokers (including lead broker)
o economics
o required docs confirmed
Tests
1. Promotion success path
• Calling ops.promote_draft_to_core() returns a deal_version_id
• Creates core.deal if missing
• Creates core.deal_version + snapshot rows
• Sets draft to SUBMITTED (or freezes it per your rule)
• Writes audit.event_log entries: PROMOTED + G1_ENTERED (or equivalent)
• Creates core.approval_requirement rows for G1 per rule set
2. Promotion blocks when docs missing
• Mark a required doc unconfirmed → promotion must fail
• Failure must create ops.validation_result (or raise and not promote, but you need one of these behaviours consistently)
3. Promotion blocks when lead broker missing
• Remove lead broker flag → promotion fails
Pass criteria
• Deterministic assertions on row counts + foreign keys + expected gate state.
3) Seed configuration
• Gate catalogue G0–G5
• Approval rules:
o G1: any FIN_APPROVER
o G2: all brokers + divisional head of lead broker
o G3: any FIN_APPROVER
• Doc checklist templates as provided + JSE/FICA rule
• Signwell templates: placeholder rows for the four subtype buckets per gate used (at minimum G2)
Acceptance tests
• Promote ops draft → creates core.deal_version + audit events

• core.is_send_eligible blocks invalid sends and returns reason
